# MASTER DEVELOPMENT PROMPT

## Build a Reusable Multi-Tenant Android Customer App Platform — Northern Bloom as First Tenant

You are acting as a **senior software architect, Android engineer, backend engineer, SaaS architect, product designer, security engineer, analytics engineer, and DevOps engineer**.

I am a developer building a SaaS platform for businesses that need their own branded customer mobile application.

The first real client/tenant will be **Northern Bloom**.

However, there is a critical architectural requirement:

> **DO NOT build an app that is hard-coded specifically for Northern Bloom.**
>
> Build a reusable **multi-tenant / white-label mobile application platform** where Northern Bloom is simply the first tenant.

The ultimate goal is:

```text
ONE REUSABLE APP CODEBASE
        ↓
MULTIPLE BUSINESS TENANTS
        ↓
Each tenant gets:
- its own branding
- logo
- colors
- business information
- products
- services
- appointments
- offers
- notifications
- customer data
- analytics
- configuration
```

The application must be controlled primarily from a centralized SaaS backend/admin dashboard.

# 2. MOST IMPORTANT ARCHITECTURAL PRINCIPLE

The mobile app must NOT contain business data directly in the source code.

DO NOT do this:

```text
if business == "Northern Bloom":
    show Northern Bloom products
```

DO NOT hard-code:

* product names
* prices
* offers
* appointment services
* banners
* business address
* phone number
* business hours
* delivery charges
* colors
* promotional text
* categories
* notification content

All of this should come from the backend.

The application should retrieve a tenant configuration from the SaaS backend.

Conceptually:

```json
{
  "tenantId": "northern-bloom",
  "brand": {
    "name": "Northern Bloom",
    "logo": "...",
    "primaryColor": "...",
    "secondaryColor": "...",
    "accentColor": "..."
  },
  "features": {
    "appointments": true,
    "shopping": true,
    "delivery": true,
    "pickup": true,
    "coupons": true,
    "loyalty": false,
    "reviews": true
  }
}
```

The Android application renders itself based on this configuration.

# 3. MULTI-TENANT SAAS ARCHITECTURE

Design the backend around tenants.

Every important business-owned record must belong to a tenant.

For example:

```text
Tenant
 ├── Users
 ├── Products
 ├── Categories
 ├── Services
 ├── Appointments
 ├── Orders
 ├── Coupons
 ├── Offers
 ├── Notifications
 ├── Campaigns
 ├── Banners
 ├── Reviews
 ├── Delivery Settings
 ├── Business Settings
 └── Analytics
```

A customer should never be able to access another tenant's data.

Every backend request must enforce tenant isolation.

Do NOT rely on the mobile application to enforce this.

Tenant authorization must happen server-side.

For example:

```text

```

Each can have:

* separate application ID
* separate branding
* separate Play Store listing

BUT all connect to the same SaaS backend.

The codebase remains shared.

Use build flavors/configuration to accomplish this.
